# Профиль `CHANGE` — «изменение»

Применять вместе с `task_core_v01.md` для изменения кода, документации,
конфигурации или рабочего процесса ML-CRA.

## Дополнительные обязательные поля

Определить:

- изменяемое поведение или состояние;
- разрешённые классы файлов;
- защищённые файлы и инварианты;
- ожидаемый планируемый набор изменений;
- обязательные регрессионные проверки;
- правила восстановления;
- является ли блок значимым и требует ли ZIP.

## Профильные правила

1. Зафиксировать воспроизводимое состояние до изменения.
2. Сформировать минимальный планируемый набор изменений и сразу продолжить.
3. Не изменять научный claim, протокол или численные результаты, если это не
   разрешено прямо.
4. Исправлять только дефекты, необходимые для принятого результата.
5. Для каждого незапланированного файла применить семь условий постоянного
   контракта.
6. После выполнения сравнить планируемый набор и журнал фактических изменений.
7. Для `.py` и `.ipynb` сохранить точные доказательства
   `Как было → Как стало`.

## Профильные доказательства

- исходная контрольная сумма или manifest, когда применимо;
- планируемый набор изменений;
- журнал фактических изменений и объяснение отклонений;
- команды, среда, коды завершения и результаты проверок;
- подтверждение сохранения защищённых артефактов;
- доказательная запись;
- ZIP и SHA-256 для значимого изменяющего блока.
