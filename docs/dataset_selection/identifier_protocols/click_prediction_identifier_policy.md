# Протокол обработки идентификаторных признаков: openml_click_prediction_small_41434

## 1. Статус

Этот протокол относится только к кандидату:

```text
openml_click_prediction_small_41434
```

Набор данных остается условным кандидатом. Протокол не принимает его в первую минимальную версию и не запускает обучение моделей.

## 2. Идентификаторные признаки

По результатам первичного просмотра данных подозрительными идентификаторными признаками считаются:

1. `url_hash`;
2. `ad_id`;
3. `advertiser_id`;
4. `query_id`;
5. `keyword_id`;
6. `title_id`;
7. `description_id`;
8. `user_id`.

Эти признаки нельзя автоматически считать плохими. Но их нельзя и автоматически принимать как обычные признаки без аудита.

## 3. Главный риск

Главный риск:

> будущая модель может выигрывать не за счет устойчивой обобщаемой закономерности, а за счет запоминания идентификаторов.

Для ML-CRA это особенно важно, потому что проект проверяет надежность утверждения, а не просто максимальный результат метрики.

## 4. Разрешенные политики

### 4.1 Безопасная базовая политика

Исключить все идентификаторные признаки.

Это основная безопасная политика для первой версии.

Назначение:

1. получить консервативную базовую постановку;
2. проверить, существует ли сигнал без идентификаторов;
3. иметь контрольную точку для сравнения с более рискованными политиками.

### 4.2 Условная диагностическая политика

Оставить идентификаторы с ограниченным кодированием категорий.

Условия:

1. разбиение данных выполняется до подгонки кодировщика;
2. кодировщик обучается только на обучающей части;
3. редкие категории ограничиваются или объединяются;
4. неизвестные категории в проверочной/тестовой части обрабатываются явно;
5. результат сравнивается с безопасной политикой исключения идентификаторов.

### 4.3 Отложенная политика

Целевое кодирование с внутренней перекрестной подгонкой.

Эта политика не входит в первый минимальный контур. Она может быть добавлена позже, потому что неправильное целевое кодирование особенно рискованно для утечки целевой переменной.

## 5. Запрещенные политики

Запрещено:

1. кодировать категориальные признаки на полном наборе данных до разбиения;
2. использовать целевое кодирование без внутренней перекрестной подгонки;
3. принимать идентификаторы как обычные признаки без сравнения с безопасной политикой;
4. делать claim о превосходстве модели только на постановке с идентификаторами;
5. считать высокий результат доказательством без проверки политики идентификаторов.

## 6. Минимальный диагностический порядок

До обучения моделей нужно сделать:

1. зафиксировать список идентификаторных признаков;
2. посчитать число уникальных значений для каждого;
3. посчитать долю редких категорий;
4. проверить, сколько раз встречается `user_id`;
5. решить, возможно ли групповое разбиение по `user_id`;
6. утвердить безопасную базовую политику;
7. только после этого переходить к обучению моделей.

## 7. Решение

Для первой минимальной версии ML-CRA:

1. основная политика — исключить идентификаторные признаки;
2. диагностическая политика — оставить идентификаторы только в отдельной чувствительной проверке;
3. целевое кодирование — отложить;
4. claim по `Click_prediction_small` считается слабым или условным, если он подтверждается только при использовании идентификаторов.
