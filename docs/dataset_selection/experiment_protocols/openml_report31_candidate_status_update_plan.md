# План REPORT_31 — обновление ролей и статусов OpenML-кандидатов

## Назначение

Следующий шаг должен не обучать новые модели, а перевести результаты двух диагностических контуров в проверяемое решение по ролям кандидатов.

## Предлагаемые роли

1. `openml_miniboone_41150` — основной стабильный табличный кандидат (`primary_tabular_candidate`).
2. `openml_electricity_151` — кандидат для проверки временной чувствительности (`temporal_sensitivity_candidate`).
3. `openml_click_prediction_small_41434` — диагностический кейс риска идентификаторных признаков (`leakage_risk_diagnostic_or_hold`).

## Ограничение

## Требование к следующему шагу
