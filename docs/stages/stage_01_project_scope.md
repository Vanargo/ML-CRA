# Этап 1 — постановка задачи и границы ML-CRA

## 1. Назначение документа

Этот документ является рабочим документом этапа 1. Он заменяет необходимость обращаться к нескольким ранним отчетам, когда нужно восстановить смысл проекта, объект проверки, гипотезу, исследовательские вопросы и границы минимальной версии.

## 2. Статус этапа

Статус: базово завершен. Этап можно редактировать только для уточнения публичной формулировки, но нельзя менять объект проекта без отдельного решения.

## 3. Название и объект проекта

Проект называется ML Claim Reliability Auditor, сокращенно ML-CRA; русское название — «Аудитор надежности утверждений в ML-экспериментах». Текущая архивная копия источника: `docs/archive/reports/REPORT_04_project_definition.md`, страница: не применяется, раздел `Working name`, строки 3–13. Дословный фрагмент: «ML Claim Reliability Auditor ... ML-CRA ... We build a tool that checks not “which model is best”, but whether we have enough evidence to claim that a model is better».

Центральный объект проекта — не модель, не набор данных и не метрика, а экспериментальное утверждение о превосходстве, устойчивости или практической предпочтительности модели. Это следует из исходного раздела об объекте проекта, где центральный объект прямо назван `Experimental claim`. Текущая архивная копия источника: `docs/archive/reports/REPORT_04_project_definition.md`, страница: не применяется, раздел `2. Object of the project`, строки 37–51. Дословный фрагмент: «The central object is not a model, not a dataset, and not a metric. The central object is: Experimental claim».

## 4. Проблема

Типичный вывод «Model A is better than Model B because it has a better score...» может быть хрупким, потому что зависит от разбиения, зерна случайности, метрики, предобработки, дисбаланса, шума, утечки, размера эффекта и вычислительной стоимости. Текущая архивная копия источника: `docs/archive/reports/REPORT_04_project_definition.md`, страница: не применяется, раздел `1. Problem statement`, строки 17–35. Дословный фрагмент: «Model A is better than Model B because it has a better score on ROC-AUC, F1, RMSE, MAE, or another metric ... How reliable is the claim that this model is actually better?».

Следствие для проекта: любой будущий результат вида «модель лучше» должен проверяться как утверждение, а не приниматься по одной строке метрики.

## 5. Формальное определение

ML-CRA определен как исследовательский проект по проверке надежности экспериментальных утверждений в табличном обучении с учителем. Ожидаемые выходы включают технический отчет, воспроизводимый проверочный контур, командный инструмент, обзорную панель, двуязычную документацию и открытый репозиторий. Текущая архивная копия источника: `docs/archive/reports/REPORT_04_project_definition.md`, страница: не применяется, раздел `3. Formal project definition`, строки 53–73. Дословный фрагмент: «ML-CRA is a modular, research-grade Data Science / Machine Learning project that develops a local open-source tool for evaluating the reliability of experimental claims in supervised tabular ML ... research-oriented technical report; reproducible benchmark pipeline; CLI tool; dashboard; bilingual documentation; public GitHub repository».

## 6. Главная гипотеза

Главная гипотеза: вывод «эта модель лучше» часто оказывается хрупким при переходе от одного запуска к серии контролируемых проверок. Текущая архивная копия источника: `docs/archive/reports/REPORT_04_project_definition.md`, страница: не применяется, раздел `4. Main hypothesis`, строки 75–81. Дословный фрагмент: «Во многих ML-экспериментах вывод «эта модель лучше» оказывается хрупким, если проверить его не одним запуском, а серией контролируемых проверок».

## 7. Исследовательские вопросы

Этап фиксирует шесть управляющих вопросов: устойчивость к зерну случайности, чувствительность к протоколу разбиения, конфликт метрик, размер эффекта, стоимость качества и итоговую категорию надежности утверждения. Текущая архивная копия источника: `docs/archive/reports/REPORT_04_project_definition.md`, страница: не применяется, раздел `5. Research questions`, строки 83–138. Дословный фрагмент: «RQ1. Random seed stability ... RQ2. Split protocol sensitivity ... RQ3. Metric conflict ... RQ4. Effect size ... RQ5. Cost of quality ... RQ6. Claim verdict».

## 8. Минимальная версия

Минимальная версия ограничена табличной классификацией и регрессией. Полная автоматизация машинного обучения, крупные глубокие проверочные наборы, производственный мониторинг и ряд других направлений исключены из минимальной версии. Текущая архивная копия источника: `docs/archive/reports/REPORT_04_project_definition.md`, страница: не применяется, раздел `6. MVP scope`, строки 140–187. Дословный фрагмент: «Included in MVP ... tabular classification; tabular regression ... Excluded from MVP ... Full AutoML ... Large-scale deep learning benchmarks».

## 9. Критерий готовности этапа

Этап 1 считается готовым, если:

1. пользователь и будущий читатель понимают, что ML-CRA не является соревнованием моделей;
2. объектом проверки является утверждение;
3. зафиксированы исследовательские вопросы;
4. зафиксированы включения и исключения минимальной версии;
5. следующий этап может выбирать данные под проверку надежности утверждений, а не под получение красивого результата.
